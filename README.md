# 🚗 Car Price Predictor — End-to-End ML System

An end-to-end machine learning system that estimates the resale value of a used car.
It covers the full lifecycle: data preprocessing, model training with hyperparameter tuning,
a REST API to serve predictions, and a cross-platform Flutter app.

## ✨ Features

- **Robust preprocessing pipeline** — handles missing values, categorical encoding and feature scaling inside a single scikit-learn `Pipeline` (no train/serve skew, no data leakage).
- **Model comparison and tuning** — Random Forest vs XGBoost, tuned with `RandomizedSearchCV`; the winner is chosen on cross-validation and evaluated once on a holdout test set.
- **Honest uncertainty** — every prediction comes with a likely price range derived from holdout residuals.
- **Scalable FastAPI backend** — stateless, validated inputs (Pydantic), Docker-ready, 10 automated tests.
- **Responsive Flutter app** — Android, iOS, web and desktop from one codebase, with live form validation and offline handling.

## 🏗️ Architecture

```
 cars.csv ──► ml/train.py ──► artifacts/{model.joblib, metrics.json, meta.json}
                 │                          │
  clean ► holdout split ► tune RF + XGB     │ loaded once at startup
  (CV on train only)  ► evaluate on test    ▼
                                    FastAPI  (GET /health · GET /meta · POST /predict)
                                            ▲
                                            │ JSON over HTTP
                                    Flutter app (Android / iOS / web / desktop)
```

## 📊 Model Performance

Evaluated on a **20% holdout test set** (1,800 cars) that was never used for tuning or model selection.

| Metric | XGBoost (selected) | Random Forest |
|--------|-------------------:|--------------:|
| MAE    | ₹40,442            | ₹58,374       |
| RMSE   | ₹83,092            | ₹152,515      |
| R²     | 0.975              | 0.914         |
| MAPE   | 8.4%               | 11.4%         |

> ⚠️ **Note on data:** the included dataset is **synthetic** (generated by
> `backend/data/generate_synthetic_data.py`) so the project runs with zero downloads.
> The numbers above demonstrate that the pipeline works, not real-world accuracy.
> To use real data, see [Using a real dataset](#-using-a-real-dataset).

### Key design decisions

| Concern | Choice | Why |
|---|---|---|
| Missing values | Median / most-frequent imputation + missing-indicator flags | Optional API fields "just work" at serving time |
| Categorical encoding | `OneHotEncoder(handle_unknown="ignore")` | Unseen brands degrade gracefully instead of crashing |
| Scaling | `StandardScaler` | Keeps the pipeline model-agnostic |
| Target | `log1p(price)` | Prices are skewed; errors are proportional |
| Leakage prevention | Everything lives in one `Pipeline`, fit on train folds only | Test statistics never leak in |
| Tuning | `RandomizedSearchCV`, 3-fold, MAE | Model selected on CV, not on the holdout |

## 🚀 Getting Started

### Prerequisites
- Python 3.10+
- Flutter 3.x SDK (for the app)

### 1. Backend

```bash
cd backend
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python data/generate_synthetic_data.py     # skip if you add your own cars.csv
python -m ml.train                         # trains + saves artifacts/ (~2–3 min)
python -m pytest -q tests                  # run the API tests

uvicorn app.main:app --reload --port 8000
```

Interactive API docs: <http://localhost:8000/docs>

### 2. Flutter app

```bash
cd flutter_app
flutter create .          # generates android/ ios/ web/ folders around lib/
flutter pub get
flutter test

# Android emulator (auto-uses 10.0.2.2:8000)
flutter run

# Physical device or custom server
flutter run --dart-define=API_BASE_URL=http://<your-LAN-IP>:8000
```

**Dev note (plain HTTP):** Android needs `android:usesCleartextTraffic="true"` on the
`<application>` tag in `AndroidManifest.xml`; iOS needs an ATS exception.
Serving the API over HTTPS avoids both.

### 3. Docker

```bash
cd backend
docker build -t car-price-api .
docker run -p 8000:8000 car-price-api
```

## 🔌 API Reference

### `POST /predict`

```bash
curl -X POST http://localhost:8000/predict \
  -H "Content-Type: application/json" \
  -d '{
    "brand": "Hyundai",
    "year": 2019,
    "km_driven": 45000,
    "fuel": "Petrol",
    "transmission": "Manual",
    "owner": "First",
    "seller_type": "Individual",
    "mileage": 18,
    "engine": 1197,
    "max_power": 82,
    "seats": 5
  }'
```

`mileage`, `engine`, `max_power` and `seats` are optional; omitted values are imputed.

**Response**

```json
{
  "predicted_price": 346000,
  "currency": "INR",
  "range_low": 302000,
  "range_high": 396000,
  "confidence_note": "80% of similar holdout cars sold within this band (typical error ~8%).",
  "model_name": "xgboost",
  "imputed_fields": []
}
```

### Other endpoints

| Method | Path       | Description                                          |
|--------|------------|------------------------------------------------------|
| GET    | `/health`  | Liveness + whether the model is loaded               |
| GET    | `/meta`    | Dropdown options, value ranges and holdout metrics   |

Invalid input returns `422` with a readable message (e.g. impossible odometer reading).

## 📱 App Highlights

- Responsive layout: single column on phones, form + result side by side on tablets/desktop/web.

- Prices formatted with Indian digit grouping (₹3,46,000).

## 📦 Using a real dataset

Place a CSV at `backend/data/cars.csv` with these columns:

```
brand, year, km_driven, fuel, transmission, owner, seller_type,
mileage, engine, max_power, seats, selling_price
```

For example, the CarDekho used-car dataset on Kaggle (split its `name` column to get `brand`,
and strip units such as `kmpl`, `CC`, `bhp`). Then re-run `python -m ml.train` — the API,
dropdowns and metrics update automatically.
